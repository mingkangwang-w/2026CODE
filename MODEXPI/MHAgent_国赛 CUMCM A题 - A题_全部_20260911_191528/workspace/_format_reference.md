# Markdown 格式自检对照表（comp_cumcm 工作流参考）

> 此文件仅作为 docx-format-check 步骤的**自检对照参考**，不参与渲染、不当模板。
> 具体格式要求由 docx-export 渲染引擎按 `competition_zh.json` 应用。
（注：本规范的字号字体边距由实测自一份完整论文样本：`main.docx`）

**核心规范摘要**：数学建模竞赛中文论文（对标 cumcmthesis.cls）：A4 纸 25mm 边距，正文宋体小四 12pt 1.5 倍行距，章节用「一、二、三、」中文序号。

## 一、页面与正文规范

- 纸张：A4
- 页边距：上 2.5 cm / 下 2.5 cm / 左 2.5 cm / 右 2.5 cm
- 正文字号：12 pt（中文小四号）
- 正文行距：1.5 倍
- 首行缩进：2 个汉字字符宽度
- 中文正文字体：SimSun
- 中文标题字体：SimHei
- 西文字体：Times New Roman
- 等宽字体（代码）：Consolas

## 二、Markdown 标题层级与渲染映射

| Markdown 写法 | 渲染字号(pt) | 加粗 | 对齐 | 用途 |
|--------------|------------|------|------|------|
| `# 论文题目` (整篇唯一) | 18 | 是 | center | 论文/报告题目（自动用 title 样式） |
| `## 摘要 / Abstract` | 14 | 是 | center | 摘要标题（引擎特殊路径） |
| `## 一、问题重述 / ## 1 引言` | 14 | 是 | left | 一级章节 |
| `### 1.1 小节名` | 12 | 是 | left | 二级小节 |
| `#### 1.1.1 子节名` | 11 | 是 | left | 三级子节（慎用） |

⛔ **关键铁律**（按引擎实际行为）：

1. **整篇论文 `#` 只用一次**（论文题目），所有正文章节从 `## ` 起步。如果你写了多个 `#` 标题，第二个开始就会按"二次 H1"渲染（落到 `level1_pt`，可能不是你想要的样式）。
2. **`## 摘要` / `## Abstract` / `## Summary` 自动走特殊样式**（14pt 居中加粗）— 这是引擎硬编码识别的，你不需要做任何特殊操作，但**摘要标题必须正好是 「摘要」/「Abstract」/「Summary」**，不要写成"摘要：" / "## 摘 要" / "## ABSTRACT"。
3. **`**关键词**：xxx, yyy, zzz`** 也走特殊路径（黑体加粗标签 + 正文内容，独占一行段落）。**注意：本工作流的关键词标签字体是 SimHei**，正文是 SimSun。
4. **章节用 `#` 开头**，禁止 `- 章节名`（list 项 → 渲染成 "•"）。

⛔ **铁律：标题必须用 `#` 开头**，禁止用 `- 章节名`（list 项）伪装标题，否则 docx 引擎会渲染成"• 章节名"。

## 三、推荐章节骨架（仅供结构对照，不要照搬具体名称）

按 `comp_cumcm` 工作流的特点，建议骨架如下：

```
# 论文题目（H1）
  ## 摘要（H2）  ← ⚠ 自动居中加粗（引擎特殊路径，必须正好是「摘要」/「Abstract」/「Summary」）
  **关键词**：xxx, yyy, zzz    ← ⚠ 普通段落（不是 heading），引擎自动用黑体加粗标签
  ## 一、问题重述（含问题背景与待解决的问题）（H2）
  ## 二、问题分析（H2）
  ## 三、模型假设与符号说明（H2）
    ### 3.1 模型假设（H3）
    ### 3.2 符号说明（H3）
  ## 四、模型建立与求解（H2）
    ### 4.1 问题一：xxx 模型（H3）
    ### 4.2 问题二：xxx 模型（H3）
  ## 五、模型评价（优缺点 / 推广 / 灵敏度）（H2）
  ## 参考文献（H2）
  ## 附录（可选）（H2）
```

⛔ **本骨架是"参考结构"不是"必须项"**：
- 论文/报告应包含的核心模块在表里都列了
- 具体章节名可以根据论文实际内容调整（"问题一/问题二" / "方法一/方法二" / 主题分类等）
- H2 是一级章节；H3 是二级小节；H4 是三级子节
- 不要为了凑骨架而强行填充空章节

## 四、图/表注释规范

⛔ **题注铁律**：
- 图：`图 X：说明文字` 或 `图 X-Y：说明文字`（X 是章节号或全文流水号）
- 表：`表 X：说明文字`
- **题注独占一行**，紧跟在图/表的下面（图在题注下方，表在题注上方更规范，但 markdown 引擎都能识别）
- ⛔ 不要写成 `- 图 X：xxx`（list 项 → 渲染出 "•"）
- ⛔ 不要写成 `**图 X**：xxx`（加粗 + 冒号会被识别成正文加粗段）
- 题注是图/表的灵魂，必须**简短具体**（不超过 30 字），点明这张图/表说明什么

正确范式样例：

```
![](figures/fig_main.png)
图 1：核心模型流程示意图

| 列1 | 列2 |
|---|---|
| ... | ... |
表 1：实验结果对比
```

## 五、公式编号规范

⛔ **公式铁律**：
- 块公式必须独占行：`$$ y = ax + b $$`
- 编号必须**与公式同行**，不能写在下一行：
  - 对：`$$ y = ax + b $$ (1)` 或 `$$ y = ax + b \tag{1} $$`
  - 错：`$$ y = ax + b $$\n- (1)` （编号被渲染成 list bullet）
- 全文按出现顺序连续编号 `(1)(2)(3)...`，不跳号、不重复
- 行内公式用单 `$..$`：`$E=mc^2$`，**不用** `$$..$$`

## 六、加粗使用规则

⛔ **加粗使用规则**：
- 关键词标签 `**关键词**：` 加粗
- 假设/定理标签 `**假设一**：` `**定理 1**：` 加粗
- 章节标题已自带加粗，不要再用 `**`
- ⛔ 不要整段加粗（一段全是 `**...**`）
- ⛔ 不要用加粗当强调，过多加粗反而稀释重点

## 七、表格规范

- 三线表样式：顶线 1.5 pt + 表头线 0.75 pt + 底线 1.5 pt
- 表头加粗：True
- 单元格对齐：center
- 字号：10.5 pt（小五号）

⛔ **Markdown 表格铁律**：
- 用纯 Markdown 表格语法 `| ... | ... |`，**禁止** LaTeX `\begin{tabular}`
- 第二行必须是分隔行 `|---|---|...|`
- 每行列数一致
- 数据来源优先 `figures/TABLE_*.md`（已生成的真实数据），不要凭记忆手抄

## 八、图片规范

- 引用语法：`![图 X：图题](figures/fig_xxx.png)`
- ⛔ 必须 `.png`，不能 `.pdf`（Word 不能嵌 PDF）
- alt 文本同时作为图题（自动渲染）
- 最大宽度：14 cm
- 对齐：center

## 九、参考文献规范

- 上标引用：`[1]` `[2,3]` `[4-6]`
- 不要用 `\cite{}` `\ref{}`
- 文献格式：`[1] 作者. 题名[J]. 期刊, 年, 卷(期): 页码.`
- 行间距：悬挂缩进 0.74 cm
- 字号：10.5 pt

3. ☐ 块公式编号与公式同行，没有独立的 `- (1)` 行

8. ☐ 没有 LaTeX 残留（`\begin{}` `\section{}` `\cite{}`）
