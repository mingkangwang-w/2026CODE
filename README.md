# 2026年国赛代码储存

用于存储比赛时不同版本与方案的代码，建议大家在 VS Code 中直接使用 Git 来管理版本和协作。

---

## 一、在 VS Code 里怎么用 Git

最常用的操作，基本都在左下角和顶部工具栏里完成：

1. 先打开项目文件夹
2. 看左下角是否有 Git 分支状态
3. 点击源代码管理按钮（Source Control）
4. 进入提交、拉取、推送等操作
5. 用分支来进行多人协作

下面按“按什么按钮、点哪里、下一步做什么”的顺序说明。

---

## 二、第一次打开项目时

### 1. 打开仓库

在 VS Code 中，打开项目文件夹后，通常会自动识别是否是 Git 仓库。

你可以看左下角：

- 如果出现分支名，例如 main、master
- 或者右下角有 Git 状态图标

说明这个项目已经连接到 Git。

### 2. 看见“源代码管理”按钮

左侧边栏中间位置，有一个图标，叫做：

- Source Control
- 源代码管理

点击它，就会看到：

- 已修改文件
- 未跟踪文件
- 提交区
- 分支信息

这就是 Git 的主界面。

---

## 三、如何使用 git pull（拉取最新代码）

### 什么时候用

当你开始做代码之前，或者别人已经提交了代码，你需要更新本地版本时，先执行拉取。

### 在 VS Code 里怎么操作

1. 点击左下角分支名
2. 选择当前分支，例如 main
3. 右键点击或点击“...”菜单
4. 选择“Pull”或“Pull from...”
5. 选择对应的远程仓库和分支

### 适用场景

- 你刚进来开始写代码
- 其他队友提交了新内容
- 发现本地代码不是最新版本

### 重点提示

在每次开始写代码前，最好先执行一次拉取，避免覆盖别人写的内容。

---

## 四、如何使用 git push（上传代码）

### 什么时候用

你做完修改、测试通过后，需要把内容上传到远程仓库时，使用推送。

### 在 VS Code 里怎么操作

1. 点击左侧“源代码管理”按钮
2. 查看修改过的文件
3. 输入提交说明，例如：
   - 完成算法改进
   - 修复参数问题
   - 增加实验方案
4. 点击“提交”按钮，先提交到本地
5. 然后点击“推送”按钮，上传到远程仓库

### 典型流程

- 写代码
- 修改文件
- 点击 Source Control
- 输入提交信息
- 点击提交
- 点击推送

### 注意

如果你当前不在主分支，而是在自己的分支上，那么推送时会推送到当前分支，而不是自动提交到 main。

---

## 五、如何提交代码（Commit）

提交代码在 VS Code 中是非常重要的一个步骤。

### 操作步骤

1. 打开 Source Control
2. 在修改的文件列表中查看变动
3. 选择要提交的文件，或者直接提交全部
4. 在输入框中写说明，例如：
   - 修复输出错误
   - 更新比赛方案
   - 添加测试数据
5. 点击“Commit”按钮

### 提交说明的写法

提交信息建议简洁明确，最好写成：

- 修复路径错误
- 优化参数设置
- 完成第一个方案测试

不要写得太长，但一定要能看懂这次改了什么。

---

## 六、如何切换分支（branch）

分支是多人协作最重要的方式，作用就是让每个人在自己的“代码线”里工作，不互相打扰。

### 在 VS Code 里怎么做

1. 点击左下角的分支名
2. 选择“Create new branch”或者“新建分支”
3. 输入分支名称，例如：
   - zhangsan-algorithm
   - li-si-debug
   - feature-scheme-1
4. 回车确认

### 常见分支命名

- main：主分支，通常放稳定版本
- feature/xxx：功能分支
- bugfix/xxx：修复分支

### 什么时候需要分支

- 你在做一个新的方案
- 需要单独调试代码
- 不想影响其他人当前的版本

---

## 七、如何在分支上协作

### 推荐流程

1. 先在 main 分支上拉取最新代码
2. 点击分支名，创建自己的分支
3. 在自己分支中写代码
4. 提交并推送到自己的分支
5. 让队友检查代码
6. 等测试稳定后，再合并到 main

### 具体操作顺序

#### 第一步：先更新主分支

- 点击左下角分支名
- 切换到 main
- 选择 Pull

#### 第二步：创建个人分支

- 点击分支名
- 选择 Create new branch
- 命名为你的任务名称

#### 第三步：在自己的分支中写代码

- 修改代码文件
- 观看 VS Code 右侧是否显示修改状态

#### 第四步：提交和推送

- 点击 Source Control
- 输入提交信息
- 点击 Commit
- 点击 Push

#### 第五步：合并回 main

等功能完成后：

- 切回 main
- 拉取最新版本
- 再从你的分支合并到 main
- 最后推送 main

---

## 八、如何解决代码冲突

冲突通常出现在两个人同时改同一个文件时。

### 在 VS Code 里处理冲突的步骤

1. 看到 Git 提示“Merge conflict”或者“冲突”
2. 点击冲突文件
3. VS Code 会显示两份内容
4. 你需要手动决定保留哪一部分
5. 解决后保存文件
6. 再提交一次
7. 推送到远程仓库

### 处理冲突时要注意

- 不要直接覆盖别人的代码
- 看清冲突位置再选择保留内容
- 如果有疑问，先和队友沟通再决定

---

## 九、VS Code 里最实用的几个按钮

如果你们团队刚开始使用 Git，记住这几个位置就够了：

1. 左下角分支名

   - 用来切换分支
   - 用来创建新分支
2. 左侧 Source Control 按钮

   - 用来查看修改文件
   - 用来提交代码
3. 提交按钮（Commit）

   - 将修改保存到本地仓库
4. 推送按钮（Push）

   - 把本地提交上传到远程
5. 拉取按钮（Pull）

   - 从远程同步最新代码

---

## 十、最推荐的协作方式

对于比赛项目，建议大家这样做：

- 主分支 main 保持稳定
- 每个人单独建自己的分支
- 先拉取再开始写代码
- 写完后提交并推送到自己的分支
- 最后再合并到 main

这样做的好处：

- 不会互相覆盖代码
- 容易追踪每个人的改动
- 便于回退到某个版本
- 更适合多人协作比赛项目

---

## 十一、简单操作口诀

可以把 Git 的使用记成一句话：

- 先拉取：Pull
- 再修改：编辑代码
- 再提交：Commit
- 最后推送：Push

如果是多人协作：

- 每人一个分支
- 不在 main 上直接写代码
- 代码稳定后再合并进 main

---

## 十二、最后提醒

在 VS Code 里，Git 的界面都比较直观，主要是这几个动作：

- Pull：拉取最新代码
- Commit：提交到本地
- Push：上传到远程
- Branch：创建/切换分支
- Merge：合并分支

只要按这个顺序操作，团队协作会很顺畅。
